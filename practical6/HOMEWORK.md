# Домашнє завдання до практичного заняття №6


## 1. Чому `delay()` блокує програму, а `millis()` - ні

**`delay()`.** Ця функція - це активне очікування: процесор виконує порожній цикл, поки не мине задана кількість мілісекунд. Весь цей час головний цикл `loop()` не просувається далі, тому програма не зчитує кнопку, не опитує датчики й не змінює виходи (зокрема, не може задати нову шпаруватість у `analogWrite()`).

**`millis()`.** Ця функція лише повертає, скільки мілісекунд минуло від старту, і не зупиняє виконання. Програма в кожному проході циклу порівнює поточний час із часом останньої дії: `now - lastMeasurement >= interval`. Якщо час ще не настав, цикл одразу переходить далі й виконує інші задачі: опитує кнопку, оновлює ШІМ тощо. Завдяки цьому кілька задач виконуються «одночасно» (кооперативно, без блокування).

### Що сталося б зі скетчем, якби залишити `delay(1000)` усередині `loop()`

Припустимо, наприкінці `loop()` додано `delay(1000)`:

| Момент часу | Що відбувається |
|---|---|
| 0 мс | кнопку прочитано (не натиснута), виведено рядок, починається `delay(1000)` |
| 100-250 мс | користувач натискає й відпускає кнопку - **програма цього не бачить**, бо виконується `delay()` |
| 1000 мс | `delay()` завершився, кнопку прочитано знову: вона вже відпущена - натискання **втрачено**, світлодіод не перемкнувся |

Наслідки:

- кнопка опитується лише раз на секунду, тож швидкі натискання (тривалістю менш як ≈ 1 с) пропускаються з високою ймовірністю;
- якщо натискання все ж потрапило на момент опитування, світлодіод реагує із затримкою до 1 с;
- кілька натискань підряд зливаються в одне або губляться;
- нове значення ШІМ теж оновлювалося б лише раз на секунду (апаратний таймер ШІМ працює далі, але програма не може змінити шпаруватість).

У варіанті з `millis()` цикл виконується тисячі разів на секунду, тому кнопка опитується практично безперервно, а реакція обмежена лише часом антидребезгу (50 мс).

## 2. Чому важливий роздільник між полями

Людина читає рядок `t=8032;temp=19` «очима» й розуміє зміст за контекстом. Програма ж розбирає його за **жорсткими правилами**: ділить рядок за відомим символом, а потім кожне поле - за `=`. Тому:

- роздільник має бути символом, який **не трапляється всередині значень**. Кома була б поганим вибором, якщо значення містять десяткову кому (`21,5`): рядок `21,5,3` розібрати однозначно неможливо. `;` у числах не зустрічається;
- якщо роздільник збігається з вмістом поля або змінюється, поля зсуваються, значення потрапляють не в ті змінні, а розбір «ламається» або дає хибні дані без повідомлення про помилку;
- роздільник - частина **договору між передавачем і приймачем**; при передаванні мережею (практичне заняття №10) зміна формату з одного боку зламає приймач;
- для людини ж роздільник не має значення: вона легко прочитає і `19 / 8032`, і `8032 19`.

Приклад розбору: `"t=8032;temp=19"` → `split(';')` → `["t=8032", "temp=19"]` → `split('=')` → `t = 8032`, `temp = 19`.

## 3. Розрахунок на папері

### 3.1. Значення 10-бітного АЦП для 3,3 В при опорній напрузі 5 В

Формула АЦП ATmega328P: `ADC = Vin · 1024 / Vref` (результат обмежується максимумом 1023).

```
ADC = 3,3 · 1024 / 5 = 3379,2 / 5 = 675,84  →  675 (відкидаємо дробову частину)
```

За спрощеною формулою `Vin / Vref · 1023` отримуємо 675,18, тобто теж **675**.

Перевірка: `675 · 5 / 1024 ≈ 3,296 В` (похибка квантування < 5 мВ, крок АЦП 5000 мВ / 1024 ≈ 4,88 мВ).

**Відповідь: `analogRead()` поверне 675.**

### 3.2. Шпаруватість ШІМ для тієї самої напруги

`analogWrite()` приймає значення 0…255 (8 біт), де 255 відповідає 100 % шпаруватості (вихід постійно 5 В). Середня напруга на виході: `Vout = Vcc · D`.

```
D = Vout / Vcc = 3,3 / 5 = 0,66  →  66 %
analogWrite(pin, 0,66 · 255) = analogWrite(pin, 168)   (168,3 → 168)
```

Перевірка: `168 / 255 = 65,9 %`, середня напруга `5 · 0,659 ≈ 3,29 В`.

**Відповідь: шпаруватість ≈ 66 % (`analogWrite(pin, 168)`).**

> Примітка: пін при цьому перемикається між 0 і 5 В (≈ 490 Гц на пінах 3, 9, 10, 11), а напруга 3,3 В - це середнє значення. Щоб отримати справжню «аналогову» напругу, потрібен згладжувальний RC-фільтр.

## 4. Осмислення результату

| Критерій | `delay(1000)` | `millis()` (скетч) |
|---|---|---|
| Стан процесора між вимірюваннями | очікування, нічого не виконується | виконує цикл, опитує кнопку |
| Реакція на кнопку | до ≈ 1 с, швидкі натискання губляться | практично миттєва (антидребезг 50 мс) |
| Кілька задач одночасно | неможливо | можливо |
| Складність коду | мінімальна | трохи більша (змінні часу) |

Розрахунок: ADC = **675**, ШІМ ≈ **66 %** (`analogWrite(pin, 168)`).
